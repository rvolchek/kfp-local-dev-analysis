Hello world, both ways

The same program in each SDK: compute 2x + 5 for x in 0..9, then average the results. Comments name the matching table row.

KFP v2

In [ ]:
from kfp import dsl, Client

@dsl.component(base_image="python:3.11")  # one step, image
def fn(x: int) -> int:
    return 2 * x + 5

@dsl.component(base_image="python:3.11")
def mean(ys: list) -> float:
    return sum(ys) / len(ys)

@dsl.component(base_image="python:3.11")
def announce():
    print("mean > 10")

@dsl.pipeline                            # pipeline
def main(x_list: list = list(range(10))):
    with dsl.ParallelFor(x_list) as x:   # fan-out
        y = fn(x=x).set_cpu_limit("1")   # resources
    m = mean(ys=dsl.Collected(y.output))
    with dsl.If(m.output > 10.0):        # condition
        announce()
In [ ]:
# graph is compiled to YAML before it runs
Client(host=...).create_run_from_pipeline_func(
    main, arguments={})
# or as a local run (kfp.local):
from kfp import local
local.init(runner=local.SubprocessRunner())
main()

Flyte 2

In [ ]:
import flyte

env = flyte.TaskEnvironment(
    name="hello_env",
    image="auto",                          # image
    resources=flyte.Resources(cpu="1"))    # resources

@env.task                                  # one step
def fn(x: int) -> int:
    return 2 * x + 5

@env.task                # pipeline = parent task
def main(x_list: list[int] = list(range(10))) -> float:
    ys = list(flyte.map(fn, x_list))       # fan-out
    m = sum(ys) / len(ys)
    if m > 10.0:                           # condition
        ...
    return m
In [ ]:
# graph is built at run time, as tasks call tasks
flyte.init()
flyte.run(main)
# or as a local CLI run:
!flyte run --local hello.py main

[UNVERIFIED SLOP] Four ways to get running locally

Each tool has a path without a cluster and a path with a cluster on your laptop. The two sections below give the details for each row.

KFP v2Flyte 2 Without a cluster
KFP v2[LOE: Med]

kfp.local

  1. pip install kfp
  2. Add local.init(runner=...) to your code, and pick SubprocessRunner or DockerRunner
  3. Call my_pipeline() in Python

A code change and a runner choice.

Flyte 2[LOE: XLow]

Fully local, --local

  1. pip install flyte
  2. flyte run --local my_pipeline.py main

One flag. No code change.

With a cluster
KFP v2[LOE: High]

Your own cluster, then install KFP

  1. Make a k8s cluster (kind, k3d, or minikube)
  2. Install KFP: three kubectl commands
  3. Run with the CLI (kfp run create), the UI, or kfp.Client

You build and connect the cluster yourself.

Flyte 2[LOE: Low]

Devbox

  1. flyte start devbox
  2. flyte create config --devbox
  3. flyte run my_pipeline.py main

The cluster and the platform in one command.

Key Insight A: Flyte gives the user one set of verbs that the Flyte SDK handles quietly for either local or remote execution

The task code always calls submit(). Flyte sets one controller at startup. The controller decides how the task runs: in your local Python process, or in a pod on Kubernetes.

  • flyte.map has no separate route to the controller. It calls task.aio() for each item, so each item uses the same submit() path as a direct call.
  • @env.task comes from env = flyte.TaskEnvironment(...). There is no flyte.env object. The environment runs at definition time, not at call time. It puts the image and resources on the task. The remote controller sends them with the task spec (translate_task_to_wire). The local controller uses the image only for the cache version.
  • Sources: flyte/_task.py, flyte/_map.py, flyte/_internal/controllers/__init__.py, flyte/_run.py in flyteorg/flyte-sdk.
